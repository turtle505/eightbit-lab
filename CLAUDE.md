# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

8-bit Lab (`eightbit-lab`): a local web app that runs several agent sessions ("employees", Claude Agent SDK or Codex per employee) in parallel and shows them as a pixel-art office. The manager (user) gives instructions, assigns task cards, approves tool calls, and tracks remote GPU jobs. People-facing text is switchable Korean/English; agent-facing text is English (see **Language** below). README.md is English, README.ko.md Korean — keep both in step.

## Commands

```bash
npm run dev          # backend (tsx watch, :8787) + Vite frontend (:5173, proxies /ws) → http://localhost:5173
npm run build        # vite build web → dist/
npm start            # backend serves dist/ + websocket → http://127.0.0.1:8787
npm test             # vitest run (server/test/units.test.ts, server/test/game.test.ts)
npx vitest run -t "parsers"   # run a single describe/it by name
npm run typecheck    # tsc --noEmit over server, web, shared, scripts
npm run notify:test  # send one test push through office.notify (ntfy / webhook)
npm run update       # deployed machine (also what the top bar's Update button runs): refuse if anyone is mid-turn (GET /api/busy), else git pull → npm ci if the lock changed → build → systemctl --user restart eightbit-lab
```

No compile step for the server: it runs TypeScript directly via `tsx`, and imports use explicit `.ts` extensions (`allowImportingTsExtensions`). Persistence uses the built-in `node:sqlite` (`DatabaseSync`), so Node ≥22.13 is required — `scripts/check-node.mjs` runs before `start`/`dev:server` because ESM evaluates that import before any code in `index.ts` could check. CI (`.github/workflows/ci.yml`) runs typecheck, test and build on Node 22 and 24. Auth comes from the local `claude` CLI login (Pro/Max subscription), and for Codex employees the `codex` CLI login (ChatGPT) — there is no API key.

**Conventions** (also in `AGENTS.md`, which Codex reads — keep the two consistent). Two-space indent, single quotes, semicolons. There is no linter or formatter; `npm run typecheck` is the static check. New behaviour gets a focused case in `server/test/units.test.ts`, named by observable result (`it('rejects a stale edit', …)`). Commit subjects are short, imperative and sentence-case (`Add phone notifications and one-time scheduled tasks`). A change to documented behaviour updates `README.md`, `README.ko.md` and this file. `docs/office-guide.ko.md` is the manager's own reference for the office scene (per character and per object: lines, habits, easter eggs, URL options, what is stored where); the READMEs leave the easter eggs out on purpose, so a change to any of them is recorded there.

## Architecture

**Language (`shared/i18n.ts`).** One office-wide language (`Lang = 'ko' | 'en'`): DB `settings.language` (set by the header KO/EN button, `setLanguage`) > `office.language` (default `en`). It travels in `Snapshot.language`; a switch re-sends the whole snapshot so server-made text (default figure names, usage labels) is rebuilt. Both server and browser hold their own copy of the module state, so call sites never pass the language. Rules: every string a person reads goes through `tr({ ko, en })` at the call site (whole sentences — Korean particles don't swap word for word), evaluated at use time, never in a module-level constant; dates use `locale()`/`hhmm()`/`dowShort()`; never branch on translated text. Anything the model reads (prompts, instruction suffixes, tool descriptions/results, deny messages) is plain English; the only language-dependent line is `reportLanguageLine()`, appended to every role prompt in `openSession()`. Because it lives in the system prompt, `run()` reopens a live session (same conversation) whose `LiveSession.lang` no longer matches. Logs and feed rows keep the language they were written in.

**Team prompt (`config.ts teamPrompt`).** Committed prompts are field-neutral. Every session's prompt starts with `About this team: <office.domain>` (if set), then `roles.yaml` `common:`, then `servers:` (remote-server etiquette) only when GPU servers or non-local hosts exist (`withServers` in `index.ts`); `loadRoles(domain, withServers)` prepends it to each role, and `ProjectRegistry` gets the same string. A field-specific setup (prompts, plugin `autoAllow`) belongs in `roles.local.yaml`, merged by `id`.

**Single protocol file.** `shared/protocol.ts` defines every type that crosses the wire: `Snapshot`, `ServerMsg` (server→browser), `ClientMsg` (browser→server). Adding a feature typically means: add a message variant here → handle it in the `handle()` switch in `server/src/index.ts` → send it from `web/src/main.ts` / UI code.

**Backend data flow.**
- `server/src/index.ts` wires everything: loads config, constructs `Store`, `PermissionBroker`, `ServerRegistry`, `AgentManager`, `RoutineScheduler`, `UsageMonitor`; serves `dist/` and the `/ws` WebSocket. New clients get a full `snapshot`; afterwards only incremental messages.
- `server/src/bus.ts` is a global EventEmitter; anything calling `bus.send(msg)` is broadcast to all browsers. Components never talk to sockets directly.
- `server/src/db.ts` (`Store`): SQLite at `data/office.db` — tasks, per-employee sessions/cost/cwd, logs, routine state, jobs. Tests use `new Store(':memory:')`.

**Agents (`server/src/agents/manager.ts`).** Each role in `config/roles.yaml` becomes an `Employee` with an inbox. `instruct()` queues work; `pump()` enforces a global `maxConcurrent` (subscription rate-limit protection) via a FIFO — it counts employees *mid-turn*, not open sessions. Each employee keeps **one long-lived `query()`** (`LiveSession`) whose prompt is a `MessageQueue` (push-driven async iterable): `openSession()` builds it once (resuming the stored session id, `claude_code` preset + role prompt), `consume()` streams `SDKMessage`s into status/log updates, and each `result` ends one turn (`e.endTurn`). So only the first instruction pays process start / MCP connect; measured 49.6s → 1.0s. `stop()` calls `q.interrupt()` and keeps the session; `resetSession()` closes it and drops the id; an idle session closes after `office.sessionIdleMinutes` and the next instruction resumes it. Per-turn state (`extraAllow`, permission mode) is read from `e.current` rather than closed over, and `setPermissionMode()` switches a 🔒 turn. `total_cost_usd` is cumulative per session, so only the delta is billed (a resumed session's first result is the baseline). Tests inject `queryFn`. `status.ts` maps tool names to character states (typing/running/researching/remote) shown in the game. When a run tied to a task finishes, the task moves to `review` with the last assistant text as `result`.

**Codex engine (`agents/codex.ts`, `codexTools.ts`, `codexAttachments.ts`, `codexUsage.ts`).** `EmployeeView.engine` is `'claude' | 'codex'`, stored per employee in DB `settings` (`engine:<id>`) and switched with `setEmployeeEngine` → `AgentManager.setEngine()` (only when idle; not for provider/Ollama roles). `run()` hands a codex employee to `runCodex()`: one `CodexTurn` per instruction spawns `codex app-server --listen stdio://` (locally, or over the host's shared ssh connection with `HostConfig.codexPath` for a remote host) and speaks its JSON-RPC (`initialize` → `thread/start|resume` → `turn/start`). There is no long-lived session: the thread id is kept in `settings` under `codex-thread:<role>:<host>` (separate from the Claude session, so switching back resumes the Claude conversation), and the role prompt + `reportLanguageLine` + the instruction (+ the office skill text when it names `office:<skill>`) go into each turn's input. The office/lab MCP servers are reused through an in-process MCP link (`CodexTools`, exposed as `office.X`/`lab.X` dynamic tools); a tool call outside `autoAllow`/skill rules goes to `PermissionBroker` like any approval. Codex's own command/file approval requests also become approval cards, except that in auto mode `codexAutoApproval()` accepts routine ones — never lab/ssh commands (`needsLabApproval`), `sudo`/`rm`/`dd`/`git push|reset|clean`, or extra filesystem grants. Sandbox is `workspace-write` with no network. Attachments for a remote host are tarred through the host's shared connection (`stageCodexAttachments`) and their paths rewritten. `CodexUsageMonitor` reads quota via `account/rateLimits/read` (no tokens) every 3 min and after codex runs, sent as `Snapshot.codexUsage` / `codexUsage` messages. **Per-task override:** `Task.engine` (set only by `create_task` `engine`, or `reviewOf`, which defaults to the engine that did *not* do the reviewed task — `planTaskEngine()` in `officeTools.ts`) flows through `assignTask` → `Work.engine`; `run()` → `turnEngine()` (ignored for provider roles) → `runOverride()`, which swaps in that engine's conversation id (`sessions` vs the codex thread setting) for the one turn and restores the default's afterwards, so `EmployeeView.engine` and the default conversation are untouched. While such a turn runs, `EmployeeView.turnEngine` holds its engine and the panel's selector shows it. Log lines carry `engine` (the conversation they belong to: `AgentManager.log()` uses `turnEngine ?? engine`, the user line uses the work's engine); the employee panel shows only the engine in view (📜 toggle: all, marked C/X). Rows from before the column were tagged once by `inferLogEngines()` (db.ts) from Codex-only line shapes. `office_status` reports each employee's default engine and both quotas (`OfficeApi.usage()`) so the lead can route around a nearly spent one.

**Lab-server guard.** `needsLabApproval()` (manager.ts) flags `mcp__lab__submit_job`/`cancel_job`/`fetch_results` and any Bash command with an `ssh`/`scp`/`rsync`/`sftp` command word. A `PreToolUse` hook (`onFailure: 'block'`) turns those into `permissionDecision: 'ask'` so they reach the approval card even in auto mode, unless the exact tool/command is in the role's `autoAllow` or an approved skill's `office-allow`. Read-only lab tools are unaffected.

**Auth (`auth.ts`).** `office.authToken` (empty = off, with a startup warning) gates the WebSocket (`verifyClient`) and every `/api` route but `/api/login`. Browsers POST the token to `/api/login` and get an HttpOnly SameSite=Strict cookie; scripts send `X-Office-Token`. `tokenMatches` hashes both sides before `timingSafeEqual`, so length and content don't leak. Unauthenticated page loads get `loginPage()` with 401.

**Origin checks.** `allowedOrigin()` (`origin.ts`, no side effects so tests can import it) gates both `/api` and the WebSocket (`verifyClient`): loopback host, port = backend or 5173, or no Origin at all (curl/local script). WebSockets bypass CORS, so without this any page the user opens could drive the office.

**Permissions.** Each employee runs in `auto` (SDK `permissionMode: 'auto'`: a classifier approves tool calls and only unclear ones reach `canUseTool`) or `ask` (`'default'`). The setting is DB `employee_perm` (UI toggle, `setPermission`) > role `permissionMode` > `office.permissionMode` (default auto), applied from the next run. A task with `requireApproval` (🔒, set in the task form or by `create_task`) always runs as `ask` — `effectivePermission` only tightens. An agent resuming an old session may not see a new MCP tool parameter (deferred tool schemas are cached in the session) until its session is reset. `canUseTool` auto-allows tools matching the role's `autoAllow` (exact name, or a server prefix like `mcp__office` covering `mcp__office__*` — see `isAutoAllowed`). Everything else goes to `PermissionBroker`, which emits an `approval` message and blocks until the UI answers or the run is aborted.

**Workspaces (`agents/workspace.ts`).** Role `cwd` wins; else if `researchRepo` is unset, everyone shares `workspaces/shared`; else `useWorktree` roles get a git worktree `workspaces/wt-<id>` on branch `office/<id>` of the research repo.

**In-process MCP servers (`server/src/mcp/`).** `labTools` (`mcp__lab__*`, every employee): GPU server listing, job submit/status/tail/cancel/fetch, backed by `compute/`, plus `record_result`. With no servers in `registry.list()` only `record_result` is offered, and chat characters (`isChatSeat`) then get no lab server at all. `officeTools` (`mcp__office__*`, only roles with `officeTools: true`, i.e. the secretary): office status, tasks, activity, routines, `create_task` delegation. `officeTools` reaches back into the app through the `OfficeApi` object that `index.ts` assigns to `agents.officeApi`.

**Office seating.** The server room is no longer drawn (GPU servers live in the jobs panel). `office.ts` lays desks out in a grid from `GRID_TOP` whose cell for each slot is fixed by `deskCell()` (`game/rules.ts`): slots 0–5 fill the starting 3×2 room, 6–9 add a fourth and a fifth column (the room widens first: `W` is `widthFor(cols)`, 400 + 110 per extra column), and only from slot 10 does it gain rows of five (`H` is `heightFor(rows)`). A desk never moves when another is added. `layout()` resizes the canvas and repaints when `rowsFor`/`colsFor` of the highest slot change, also when a session leaves (`upsert` with `desk < 0` removes the actor). Things on the right wall (bookshelf, clock, professor, punching bag, right plant) are placed with `rx()` so they follow the wall out; each added column gets a window. The display scale is that of the starting room and never changes with the number of desks (`resize()`): a wider room scrolls sideways inside `.office`, a taller one pushes the page down, and `reveal()` scrolls a newly selected character into view. Project sessions do not take grid slots: `layout()` sizes the room from the staff only, and a session brought into the office sits at its project's shared table in the strip right of the grid (`shared/seating.ts`: `tablePlan()` orders projects by their first session's `desk` number, which now only means "order of arrival"; two tables of four, `canSeat()` is what `ProjectRegistry.setInOffice` checks before it throws the "no seat" notice). `tableSeat()`/`tableY()` place them one table above the professor and one below (`PROF` is `H - 80`); `drawTable()` draws the table and a laptop per seat, lit while its session works. A session stays at its table when idle, shows a bubble only when not idle, and its own tag only while selected; each table has a project tag (`.table-tag`). `seat: 'reception' | 'lead'` puts an employee in the bottom strip instead of the grid; that strip, the manager, the professor and the plants are positioned relative to `H` (figures with `fromBottom` measure y up from the bottom). The professor is an employee now (`prof`, `seat: 'podium'`): drawn with `professorSprite` on his podium at `PROF`, a satire chatbot that learns lines from `workspaces/prof/quotes.md`; a name once given to the old decorative figure (`__professor`) is moved to `prof` at startup. Decorative figures are only the manager tag and the whiteboard. The same label mechanism (`FigureKey`, `renameFigure`/`figureName`, DB `employee_names` under `__<key>`) also holds the office's title (`title`, default `DEFAULT_TITLE`, 30 characters): `main.ts` `applyTitle()` puts it in the top bar's `.office-title` spans (click to rename; capitals in the game view come from CSS) and, through `setOfficeTitle()`/`viewTitle()`, in the browser tab; desktop notifications and `loginPage()` use it too. The scene's own `FIGURES` leave it out (`SceneFigure`). The manager figure is the user and mirrors what they do, all in the browser: `command.ts`, `panels.ts` and `main.ts` dispatch `office-manager` window events (`typing`, `instruct`, `approve`, `deny`) that `managerDo()` turns into typing hands, a pointing arm, a nod or a shake of the head; three minutes without input (or a hidden tab) and the manager sleeps on the desk until the next move (`touch`/`dozeOff`); minutes of activity today (`office-worked` in `localStorage`) make them yawn and nod off, less so for a while after a coffee (`tired`); six bits of mischief in a minute get noticed by the professor or Kang (`prank`, `office-caught`); a thought bubble (`.thought`) appears every few minutes from what is going on (`mutterLines`); and their eyes follow whoever is working or waiting for approval (`watched`). `?idle=`, `?mutter=` shorten the waits for trying it out. Everyone shares one body (`characterSprite`); an optional `sprite.look` swaps only the head for one large shape, a hairstyle or a hat (`LOOKS` in `sprites.ts`: spikes, bun, long, bowl, cap, beanie, ponytail, bob). Keep it to one big shape: small details (glasses, beards, props) were tried and turned to mush at this size. A look can make the figure taller, so heights go through `tallOf()` and sprites are drawn from the feet up. Kang and On have idle habits, chosen by id in `drawActor` (Kang jiggles a leg and squats, On raises her cup and nods). Easter eggs, all browser-only in `office.ts` (no server state, no model calls, deliberately not in the READMEs): five quick clicks on the professor make him angry for 20 s — red face, shouting, angry lines instead of greetings (`pokeProfessor`, `angryUntil`); clicking the wall chart gets a remark from him, the coffee machine counts today's cups (`office-coffee` in `localStorage`; from the fifth Kang and On object), the bookshelf shows a book title (`clickThing`, `remark()` for passing lines, `caption` for bubbles over things); with nobody selected Kang and On trade a line every few minutes (`banter()`, `?banter=<seconds>` to try it); venting: pressing on the papers on the manager's desk and dragging starts a throw: the dotted arc the ball would fly swings out past the pointer and back (only its first part is drawn), and releasing throws it (`throwPaper`, `land`: the professor gets angry, Kang picks the ball up and throws it back at the manager, On takes notes on a clipboard (`office-on-hits`), working staff say a line in their status bubble (`quip`), the clock, chart, bookshelf, coffee machine, plants and punching bag each react, the bin counts in `office-trash`; a ball on the floor can be pressed to throw it again, and past ten of them an idle Hana walks round picking them up (`paperChores`); `?power=0.6` pins the distance), three quick clicks on the manager's desk slam it (`clickDesk`: the room shakes), and the punching bag in the bottom-right counts hits and takes a name (`office-bag`, `office-bag-label`); module-level code in `office.ts` must not touch `location`/`localStorage` because the unit tests import it under Node. The game's logic lives outside the scene class so it can be tested: `game/rules.ts` (time of day, daily counters, plants, throw distance and landing, tiredness, `pickNew`, `stackBubbles` for bubble layout — pure functions that are handed the clock and stored values) and `game/lines.ts` (every canned line, as functions of a small context); `office.ts` keeps the canvas, the DOM and the thin `stored()`/`store()`/`clockNow()` layer. New rules and lines go in those two files with a case in `server/test/game.test.ts`; after 18:00 the room goes to dusk and then night until 06:00 and chat characters use evening greetings (`dayPhase()`; `?hour=` overrides the time); the wall clock shows the real time (`drawClock`); the two plants grow when clicked daily and wilt after three dry days, kept in `localStorage` (`office-plant-left/right`), and Kang comments on them. `seat: 'corner'` (Kang/`thug`, On/`counsel` in `roles.yaml`) stands the employee on a rug in the bottom-left corner with no desk, `desk` being its order there; `sortedEmployees()` puts them after the grid so keys 1–n stay on the working staff. Corner and podium characters (`isChat()`) talk in game-style speech bubbles instead of the status line: `main.ts` feeds `assistant` log lines to `scene.say()` (typed out over their head) and `user` lines to `scene.managerSay()` (over the manager's head); other employees' bubbles are unchanged. `layoutSpeech()` keeps the speech bubbles (chat characters, the manager's line, the bubble over a thing) from overlapping: settled from the bottom of the screen up, newer first at the same height; one that would overlap moves above the settled bubble, drops its tail and shows the speaker's name (`.stacked[data-who]`). It is recomputed only when a bubble's text or position changed. A project session is drawn only once `desk >= 0`, which `setSessionInOffice` grants from the lowest free slot and releases on the way out.

**Projects (`projects.ts`).** A project is a folder on a host (`projects` table) holding one or more sessions (`project_sessions`). A session is an employee synthesised at runtime via `AgentManager.addWorker()` with `kind: 'project'`, `desk: -1` and the project's `host`/`cwd` — so live sessions, the lab guard, approvals, logs and the feed all apply unchanged. Its id `p:<projectId>:<n>` *is* the employee id and is never reused (closing bumps the counter), so a closed session's rows can't be read as a new one. `ProjectRegistry.restore()` re-adds the workers of sessions whose host is ready (`view.ok`, so its `$HOME` is known), sends `projects` when any came back, and is safe to repeat: it runs at startup and on every `host` message that says ok, so a session on a server that answers late appears then. Until its worker exists a session is still listed by `views()` as a placeholder (`waitingView`, `desk: -1`, "waiting for the server"), and `instruct` to it is refused (`isWaiting`) — a browser that connects in the first second after a restart (every update does) must not see projects with no sessions. The web filters `kind === 'project'` out of `sortedEmployees()` (`staffOf`: number keys, staff table, assignee pickers); the command bar uses `commandTargets()` (`ui/targets.ts`), which adds the sessions that have a desk, so a seated session is instructed like anyone else. They render in the projects tab (`ui/projects.ts`), grouped by host (`groupByHost`): each host's header shows its one connection (`HostView.connected`/`sessions`/`retryInSec`, kept current by `Host.watch()`, a local `sshMux.peek()` every 20 s that sends nothing to the server), with ↻ (`recheckHost`), Disconnect (`disconnectHost`: refused while `AgentManager.busyOn(host)` is non-empty, else `closeSessionsOn` + `sshMux.close`) and a per-host add-project form whose typed text survives the tab's periodic redraw.

**SSH rate limit (`sshRate.ts`).** The campus network cuts a machine off when it sees several new ssh connections within a minute, so what is counted is *new connections*, in a sliding one-minute window per host and one for the whole machine: `SshThrottle(perMinute, total)` from `office.sshPerMinute` (default 5; `HostConfig.sshPerMinute` per host, `0` = unlimited and left out of the total) and `office.sshPerMinuteTotal` (default 4). The office's own ssh spends a slot only in `SshMux` (below). Agent commands: `SshThrottle.targetsOf()` finds every ssh/scp/rsync/sftp in a shell command (an occurrence it cannot place is left out), `sshBudgetVerdict()`, called from the PreToolUse hook and from Codex's command approval (`CodexTurn.denyCommand`), takes one slot per occurrence with `allowAll()` (all or none) and returns a verdict when there is no room; `loopsOverSsh()` (a `for`/`while`/`until … do`, `xargs`, `parallel` or `watch` around ssh) is refused outright unless the exact command is whitelisted. `sshDenyText()` is what the agent reads (a server guard, not an approval card). Slots are spent on *attempt*, so a denied approval still costs them; over-counting is the safe direction. `HostView.sshUsed/sshLimit` feed the badge.

**Permission gate.** `allowedTools` is deliberately not passed: a bare name there auto-approves before both the hook and `canUseTool`, hiding the call from the lab guard and making the SDK log CAN_USE_TOOL_SHADOWED. The `PreToolUse` hook is the single gate — it returns `ask` for lab-reaching calls, `allow` for the role's `autoAllow`/skill rules, and otherwise falls through to the auto-mode classifier and `canUseTool`.

**One ssh connection per host (`sshMux.ts`, `hosts.ts`).** Everything the office runs on a host rides one ControlMaster connection: sessions (`spawnRemote`), Codex turns and their attachments, `Host.exec`, `sshExec` GPU/job polling, `tarFetch`, and the Ollama forward (`ssh -O forward`, not a process). `sshMux.ensure(alias, { wait, force })` is the only code that opens it: it looks with `ssh -O check` (local socket, no network), and otherwise makes one attempt that every concurrent caller shares (single flight per alias), spending one budget slot (`wait: true` waits for room — a session; `wait: false` gives up — a poll). A failed attempt puts the host in a back-off (30 s doubling to 5 min) during which `ensure` answers `down` without connecting; `force` (the ↻ button → `Host.recheck()`) tries anyway. Commands then use `SSH_MUX` = `SSH_BASE` + `muxClientOpts()`: `ControlMaster=no`, the socket path, and a `ProxyCommand` that prints `eightbit-no-master` and fails, so a client whose master is gone cannot fall back to a connection of its own (ssh runs ProxyCommand only when it must connect itself). Code that cannot await (`spawnRemote`, the `CodexTurn` constructor) refuses unless `sshMux.isReady(alias)`; `AgentManager.connect()` awaits `ensure` first. Sockets live in `CONTROL_DIR` (`controlDirFor`: `data/ssh`, or a short folder under `~/.ssh` when the install path would push a socket past the ~104-byte limit). The master lingers `CONTROL_PERSIST` (10 min) after its last channel. Sessions used to keep a connection each so one drop could not close them all; that was given up on purpose — a dropped master ends its sessions with a clear log line (`consume`, ssh exit 255) and they resume on the next instruction. sshd allows about 10 channels per connection (`isChannelLimit` → a notice, never a second connection). A test (`no file in the server starts ssh without going through the shared connection`) greps `server/src` for stray `spawn('ssh'…)`. `Host.start()` still checks once and then leaves a reachable host alone; the badge can go stale and the real error surfaces on use. Tests swap the network with `setMuxDeps()`.

**Hosts (`hosts.ts`).** `office.hosts` lists machines sessions can run on. `ssh: local` is the backend's own machine (SDK spawns normally); anything else is an ssh alias and `Host.spawner()` returns a `spawnClaudeCodeProcess` that runs `ssh -T <mux options> <alias> 'cd <dir> && exec env K=V … <claude> <args>'` (a channel in the host's shared connection) — `-T` because a tty corrupts stream-json, only `CLAUDE_*`/`ANTHROPIC_*` forwarded, `claudePath` absolute because non-login ssh lacks `~/.local/bin`. MCP servers, `canUseTool` and hooks still run in the backend and ride the same pipe. `sessions.hostId` (`sessionHostId()`, which tags local sessions `backend:<hostname>`) stops a session id being resumed on a machine that never recorded it. Remote sessions get no `additionalDirectories`.

**Compute (`server/src/compute/`).** A server with `ssh_host: local` uses `localExec` instead of `sshExec` (and `fetch_results` uses `cp`), for when the backend runs on that machine. `ServerRegistry` polls servers from `servers*.yaml` and tracks jobs through an adapter per `type: ssh | slurm` (shells out to `ssh <alias>`; key auth required). `onJobFinished` re-instructs the submitting employee to report results.

**Other backend pieces.** `routines.ts` + `cron.ts`: in-house 5-field cron (local time) that calls `agents.instruct`. Routine definitions live in the DB `routines` table (soft-deleted via `deletedAt`); `config/routines*.yaml` only seeds ids never stored before. They are created/edited/deleted from the UI (`saveRoutine`/`deleteRoutine`) or by the secretary (`mcp__office__create/update/delete_routine`, never auto-allowed; deleting asks for a second `confirm()` via `confirmApprove`).

**Office skills (`skills.ts`).** Routines normally run a skill instead of a long prompt: the secretary distills the manager's request into `workspaces/office-skills/skills/<name>/SKILL.md` (`save_skill`), a local plugin named `office` that every session loads via `query({ plugins })`, so it is invoked as `office:<name>`. A skill's `office-allow` frontmatter (exact tool names or `Bash(<prefix>*)`, see `matchesRule` — commands with shell metacharacters never match) is auto-allowed only during routine runs of that skill (`instruct(..., { extraAllow })`), and only while the file's sha256 matches the manager-approved one in `skill_approvals`; an edited skill needs re-approval in the routine panel. `usage.ts`: polls subscription usage (5-hour / weekly %) via an experimental Agent SDK call using an empty session; it must degrade to "unavailable" rather than throw.

**Providers (`providers.ts`).** A role with `provider: <id>` runs on a non-Claude backend from `office.providers` instead of the subscription. Only `kind: ollama` exists: `OllamaLink` asks the host's shared connection for a forward (`ssh -O forward -L localPort:127.0.0.1:remotePort`; asked again, 30 s → 5 min apart, when the health check fails) and health-checks `/api/version` + `/api/tags` every 30 s (`provider` message). The run is the same `query()` with `env` from `ollamaEnv()` (Anthropic-compatible base URL, every model alias → the chosen model; env replaces process.env, so it spreads it) and no office-skills plugin. Provider employees bypass `maxConcurrent` with one slot per provider (`nextRunnable`), don't add to cost, and the model picked in the UI is stored in `provider_models`. A new backend kind needs its own runner, not just env.

**Frontend (`web/`, vanilla TS + Vite, no framework).** `main.ts` owns the WebSocket, a single `UIState`, and applies `ServerMsg`s then calls `renderAll()`. Three views over the same state: the canvas game (`game/office.ts`, sprites drawn in code in `game/sprites.ts`), the table-based console (`ui/console.ts`), and the reports browser (`ui/reports.ts`, styled as console via `body.view-console.view-reports`). `ui/panels.ts` holds shared panels; `ui/view.ts` switches views by physically moving shared panel elements (`command`, `approvals`, `employee`, `routines`, `jobs`, `report-feed`, `todos`) into `[data-slot]` containers of the active view (the reports view has no slots). The **command bar** (`ui/command.ts`, under the canvas / under the staff table) is the one place instructions are typed: it targets `state.selected` (character click, staff row, `1`–`n`, its own picker), is built once so typed text survives renders, and `/` focuses it. Approval cards mark risky calls (`ui/approvalRisk.ts`: deletes, git push/reset, ssh/lab jobs, sudo, curl|sh, secrets files) and show Edit/MultiEdit/Write as a line diff (`ui/diff.ts`); both are pure and unit-tested. Markdown goes through `ui/markdown.ts` (`marked` + `DOMPurify`) — never insert agent text as HTML any other way.

**Today's to-dos (`obsidian.ts`, `todos.ts`, `ui/todos.ts`).** With `obsidian.vault` set (in `office.local.yaml`), today's daily note is parsed (`parseDaily(src, NoteFormat)`: `## ` sections — all of them, or those matching `obsidian.sections`; `obsidian.schedule` ones also keep plain bullets as memo — → optional `**bold-line**` groups → `- [ ]` items with optional `↻N` carry markers, indented children and description bullets; a note with no `## ` at all is one untitled block with `line: -1`, which `add` appends to at the end; leading YAML front matter is skipped) and polled every 3 s. Edits are single-line ops (`applyTodoOp`: toggle / edit / add / delete) that carry the line number *and* its original text, so anything changed meanwhile in Obsidian is refused instead of overwritten; writes go through tmp + rename and keep the file's line endings.

**Notifications (`notify.ts`).** `office.notify` (null unless `ntfy` or `webhook` is set) → `Notifier.send(event, title, body, priority)`: events `approval` (bus `approval` msg), `result`/`error` (`runFinished`), `job` (`onJobFinished`), `scheduled`. Held back while any browser reports its tab visible (`presence` ClientMsg → `watching` set in `index.ts`, `whenAway`), capped at 20/min, never throws. The reply text goes out only with `preview: true`. ntfy titles are RFC 2047-encoded (`encodeHeader`). `npm run notify:test` sends one with `force`.

**Scheduled tasks (`schedule.ts`).** A one-off "do X at T" is a task with `startAt`: `createTask` stores the assignee but leaves it `todo` when `startAt` is more than 30 s away; `startDueTasks()` (every 20 s and at boot, so missed ones start late) runs `dueTasks()` and calls `assignTask`, which always clears `startAt` (assigning by hand = start now). The secretary passes `startAt` as local `YYYY-MM-DDTHH:mm` to `create_task` (`parseStartAt` rejects past/malformed times, naming the current time). Routines remain the tool for repeating work. **Task chains** live in the same file: a task with `afterTask` (the id of the one it follows; the form's ⛓ picker, or `create_task` `after`) waits in `todo` with its assignee while that task is unfinished (`waitsOn`), and `startFollowers()` — run when a task message reaches `review`/`done`, on `taskDeleted`, and at boot — assigns the ones that are ready (`readyFollowers`); `taskPrompt()` then appends the earlier task's result (`followBlock`). A failed predecessor stays `doing` (marked, see below), so its follower keeps waiting and its badge says so; a deleted one frees the follower with a notice instead of starting it (`orphanedFollowers`); following an already finished task starts at once. `afterTask` and `startAt` are not combined: following wins. **Halted tasks:** a card in `doing` that nobody is working on carries `Task.halt` (`'failed' | 'stopped' | 'restart'`) and, for a failure, `Task.error` (the run's last `error` log line, `clipError`). `AgentManager.settleTask()` runs in `pump()`'s `finally`, so every way a run can end is covered: a task still `doing` is marked `stopped` if the manager stopped it (`e.stopRequested`; a stopped Claude turn no longer reaches `runFinished`) and `failed` otherwise; `stop()` also marks the queued and parked cards it drops; work parked on the usage limit is left alone. A turn whose last reply carried an API error (`e.apiFailed`) counts as failed even though the CLI ends it with `success`. At boot `strandedTasks()` marks what a restart cut off. `Store.updateTask` drops the mark whenever the card is not `doing`; `assignTask` clears it and appends `retryBlock()` (what happened to the attempt before) to the prompt. `retryTask` (the ↻ button on the card and in the console) is `assignTask` with the same assignee.

**Attachments (`attachments.ts`).** The browser uploads raw bytes to `POST /api/upload?name=` (requires `X-Office-Upload: 1`; a non-localhost `Origin` is refused) → `workspaces/attachments/<date>/<id>-<safeName>`, plus a `.txt` beside it: `textutil`/LibreOffice for docx/rtf/…, and for a PDF `pdftotext` in reading order (no `-layout`) with `markPages()` turning each form feed into `--- page N ---` (dropped when `pdfTextUsable()` says it is a scan, or the tool is missing; a boot line says so); `GET /api/attachments/<id>` serves them (only DB ids). `createTask`/`instruct` carry `attachmentIds`; tasks link files through `task_attachments` (shared across tasks, e.g. when the lead forwards them via `create_task.attachments`). `attachmentBlock()` appends the absolute paths to the prompt (for a PDF with text: read the text first, open only the PDF pages needed for a figure, table or equation; `common:` in `roles.yaml` says the same for PDFs an agent fetches itself), and every session gets the folder via `additionalDirectories`. Uploads never linked or used are deleted after 24 h. Vite proxies `/api` in dev.

**Reports.** `reports.ts` scans `.md` files under `workspaces/<desk>/reports` (+ `office.reportDirs`) every 5 s; the browser can only `getReport` paths from the last scan. New/changed files and every finished run (`runFinished` bus event from `AgentManager`, labelled via `instruct(..., { label })`) become `feed` rows (DB) shown in the `📨 보고` panel (`ui/feed.ts`); edits to the same file within 10 min update its card instead of adding one.

**Topics and report layout (`shared/topics.ts`).** A task may carry a `topic` (`tasks.topic`), the research subject it belongs to: a folder-safe name (`normalizeTopic`: lower case, spaces → hyphens, a-z 0-9 hyphen, ≤40, not `daily`/`misc`/`figures`/`data`). It is set in the task form (`#task-topic`, suggestions from `knownTopics`) or by `create_task` `topic`; a following task with none inherits its predecessor's (`createTask` in `index.ts`). `taskPrompt()` adds `topicLine()`, which names the folders. Where files go is a prompt rule, not code: `common:` in `roles.yaml` ("Where files go") fixes `reports/<topic>/<date>-<title>.md`, `reports/daily/`, `reports/misc/`, `figures/`/`data/` beside the reports, `work/<topic>/` for scratch, the report header block, append-don't-overwrite and a per-topic `README.md`. `ReportFile.topic` is read back from the path (`topicOfReport`), which drives the reports tab's "by topic" tree (`#rp-bytopic`). Existing files are never moved by the app.

**Notebook (`notebook.ts`, `shared/note.ts`).** With `office.notebook` (default true) the server appends to `workspaces/notebook/<YYYY-MM-DD>.md` itself, no model call: a task's run ending (`runFinished` with a `taskId`, ok or not), a remote job ending (`onJobFinished`), a recorded result (`resultRecorded`), and the manager's `/note <text>` (`noteCommand()` in the command bar → `addNote`). `noteEntry()` builds the entry (the result's first 600 characters as a quote, files via `extractPaths()`); `Notebook.add()` only appends and never throws (one warning notice). The folder is a report root of its own (`NOTEBOOK_ROOT`, not a desk), so it shows in the reports tab and in search, but `pollReports()` makes no feed card for it.

**Updates (`update.ts`, `ui/update.ts`).** `Updater.init()` records the commit the process started on (`UpdateView.version`); `check()` (at boot, every 30 min, when a browser connects after 10 min, or `checkUpdate`; off with `office.updateCheck: false`) runs `git fetch` and counts `HEAD..@{u}` (`parseBehind`), with `ok: false` meaning "could not tell", never "up to date". The view travels as `Snapshot.update` / `update` messages; the top bar always shows a pill (the version, or "new version n" / "updating"), and opening its dialog sends `checkUpdate`. `applyUpdate` takes no arguments and runs `npm run update` (`scripts/update.ts`, unchanged: busy check → pull → build → restart) as a child, one at a time, keeping its last lines in `UpdateView.log`; it is refused while anyone is working and where `canRestart` is false (not started by systemd — `INVOCATION_ID` — or no `eightbit-lab` user unit). There is no force path from the browser. The restart kills the script with the service; the job is already with systemd by then. After a reconnect, a snapshot with a different `version` reloads the page (`versionChanged`). `Updater` takes its git/script functions as `UpdateDeps`, which is how the tests drive it.

**Experiments (`shared/experiments.ts`, `ui/experiments.ts`).** A job row can carry `topic`, `params` (the setup, name → string/number/boolean), `metrics` (name → number) and `note` (JSON text columns on `jobs`). `submit_job` takes `params`/`topic`; `mcp__lab__record_result` (`RECORD_TOOL`) merges metrics into a job by `job_id` (`Store.recordResult`), or with only `name` creates a row in state `recorded` for a run that was not an office job. A topic left out is the topic of the task the employee is on (`topicNow`). The tool reaches no server, so it is not in `needsLabApproval` and `roleAllow()` adds it to every role's auto-allow list. It emits `resultRecorded` on the bus (→ a 📊 notebook entry), and the `onJobFinished` instruction asks for it. The browser builds the table with `experimentTable()` (rows with anything recorded, columns = union of params and metrics, sort, best value per metric with `lowerIsBetter()` as the default direction) in a `<dialog>` opened from the jobs panel; `recorded` rows are left out of the remote-jobs list.

**Search (`search.ts`, `ui/search.ts`).** One box in the top bar (Ctrl/⌘+K) looks through report files, `logs`, `tasks`, `feed` and experiments (`Store.searchExperiments` over `experimentText`). There is no index: `Store.searchLogs/searchTasks/searchFeed` use `LIKE … ESCAPE` per word (`likePattern` makes `%` and `_` literal) and `ReportLibrary.search` reads the files of the last scan, caching their text by mtime. `searchTokens` lower-cases the query into at most six words that must all occur; a single ASCII character is dropped, a single Hangul syllable is a word (the browser repeats that rule in `wordsOf` for highlighting). At most `PER_KIND` (30) hits per kind, newest first. `{ t: 'search', q }` is answered with `searchResults` to the asking browser only (`reply`, like `getReport`). Report hits open the report; log, task and feed hits carry their text (capped) and open in place, rendered through `renderMd`.

## Config

`config/*.yaml` are committed defaults. Personal settings go in git-ignored `config/<name>.local.yaml`, layered by `config.ts`: `office.local.yaml` overrides keys; employee/routine/server lists merge by `id` (servers by `name`) via `mergeByKey`. Real server definitions belong in `servers.local.yaml` (copy from `servers.example.yaml`). Never put research repo paths, hosts, or personal routines into the committed files. `data/` and `workspaces/` are runtime state and git-ignored.
